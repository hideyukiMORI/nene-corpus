## テスト設計の観点

### なぜこのシナリオが必要か

| 観点 | 単発テストで不可 | 複合テストで検出可能 |
|-----|----------------|------------------|
| **状態蓄積バグ** | 1 ターンでは現れない | 10ターン後に closures が stale になる |
| **エラー後の汚染** | エラーテストは常にリセット状態 | エラー後に前のメッセージが消えるバグ |
| **二重送信の劣化** | 1回だけのテスト | 5サイクル後にガードが壊れるバグ |
| **DOM 積算バグ** | 1引用では気づかない | 25引用で stale node が検出される |
| **セッション再利用の競合** | 単純ロードテストのみ | リロード後の競合条件 |
| **大容量入力の安全性** | 通常文字数のみ | 1000字、5000字での挙動 |
